| D12 | 2026-08-10 | Run の隔離は Docker コンテナではなく **OS サンドボックス付きホストプロセス**を既定とする。**実行サーバは Linux 前提**（bwrap + cgroups / Landlock）。JS プロセス粒度の隔離は不可（エージェントが任意サブプロセスを spawn するため）、隔離は OS 層が担い、サンドボックスは既存 OS ツールの合成で実装する（新規ネイティブコードなし。必要時に runner-shim を別言語で切り出し可）。Runner バックエンドは `bwrap`（既定）/ `none`（開発用）/ `container`（オプション）。テナント分離は VM 境界（D3）が担う | 〃 |
| D13 | 2026-08-12 | **PoC では認証・クレデンシャルプロキシを実装しない**（D9 のプロキシ部分を上書き。シングルテナントで VM 内認証は過剰）。ユーザは登録制 + UI のアカウントスイッチャで切替（ログインなし・ヘッダによる申告制）。行為者は来歴（Launched-by / 承認の by）に記録する。モデル認証は実行者の CLI 認証を素通しし、従量記録はイベントログ計測で担う | バックログ B1 取り下げ、B9 |
| D14 | 2026-08-12 | 権限の第一層は**エンジンネイティブ設定へのコンパイル**。解決済み権限（Template ∩ 起動者 ∩ カードスコープ）を Claude Code の permissions 形式（allow / deny / ask。SDK の `settings` オプションで注入）等にコンパイルし、allow=自動許可 / deny=自動却下 / ask=承認ルーティングに対応させる。コンパイルはアダプタの責務（Codex は config.toml）。これは**ツール層の soft 境界**であり、「エージェントを信頼しない」原則は第二層の OS サンドボックス（D12 / B2）が担う二層構成。MCP 制御も `mcp__*` ルールで賄えるため B7 ゲートウェイは監査・レート・動的昇格が必要になるまで後ろ倒し可 | [permission/model.md](permission/model.md)、B6 |
