# 課題・ビジョン・用語

## 課題

Claude Code / Codex に代表されるコーディングエージェントは強力だが、ローカル実行が前提のため組織で使うと 3 つの限界に当たる。

1. **属人化** — エージェントは起動した個人の端末に閉じ、他のメンバーから存在も進捗も見えない
2. **ブロックの放置** — エージェントが質問や承認で人を待つとき、応答できるのは起動者だけ。起動者が離席すれば仕事が止まる
3. **権限の不在** — エージェントに「どこまでやらせてよいか」を組織として定義・強制する仕組みがない

## ビジョン

エージェントを「個人のツール」から「チームの同僚」に変える。

- 複数のユーザが複数のエージェントをリモートでローンチし、全員が同じボードで状態を見る
- エージェントには人間と同じように権限が付与され、権限を超える行動は上長の承認に回る
- エージェントの完了・失敗・承認をフックして、次のエージェントや人間のアクションにつなぐ

## 用語

| 用語 | 定義 |
|---|---|
| Workspace | 1 組織分の全体。ボード・エージェント・権限・ファイルを含む |
| Board / Card | カンバンボードとタスクカード。カードのアサイン先は人間またはエージェント |
| Agent | テンプレートからインスタンス化された**永続 ID**。権限の主体。実行そのものは持たない |
| Run | カードに紐づく 1 回の実行。起動して完了で終わるタスク型。Agent ID に紐づく |
| Template | system prompt + 権限セット + エンジン + hooks を束ねた「職務定義書」。テンプレートからの Agent 作成 = 採用 |
| Engine | Run を駆動する実体。Claude（Agent SDK）/ Codex（CLI）/ ローカル LLM |
| Hook | イベント（完了・承認等）に反応して次のアクションを起こす宣言的ルール |
| 職位ロール | メンバー / 課長 / 部長 など。権限の束と承認経路を決める |

Agent（永続 ID）と Run（使い捨て実行）を分離しているのは、権限・監査・履歴を Agent に蓄積しつつ、実行は単純なタスク型に保つため。将来「ボードに常駐して自分で仕事を拾うエージェント」に拡張する際も、権限モデルはそのまま使える。

## 差別化

既存製品（[comparison.md](comparison.md)）に対する独自性は次の交差点にある。

- 複数ユーザ共有ボード（個人の並列作業管理ではない）
- FS パス × MCP ツール粒度の権限
- 職位ベースの承認 — 日本企業の職務権限規程がそのまま ACL にマップできる
- エンジン非依存 + self-host 可能
