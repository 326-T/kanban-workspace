# ワークスペースと成果物

## 方針：汎用業務もコーディングのパラダイムで扱う（決定 D1）

対象はコーディングに限らず汎用業務まで広げる。ただし成果物の表現は**テキスト + git + diff** に寄せ、Office 的な成果物は OSS ツールチェーンでテキストからレンダリングする（docs-as-code）。

これにより、コーディング向けに成熟した仕組み — バージョン管理・差分レビュー・worktree による並列隔離・エージェントの編集能力 — が汎用業務にもそのまま効く。

## 成果物のツールチェーン

| 成果物 | ソース形式 | レンダラ | 状態 |
|---|---|---|---|
| スライド | Markdown | **Marp**（marp-cli） | 決定 |
| 文書 | Markdown | pandoc（→ PDF / docx） | 案 |
| 図 | Mermaid / SVG | mermaid-cli 等 | 案 |
| 表計算 | CSV / スクリプト生成 | 未定（xlsx が必要な場合の変換手段含む） | 未決 O6 |

レンダリングは Run の完了時（または hooks で）CI 的に実行し、生成物をカードの成果物プレビューとして添付する。レビュアーは diff（ソース）とプレビュー（見た目）の両方で確認できる。

## ワークスペースの実体

ストレージは ephemeral / shared-git / shared-volume の 3 層で構成し、層の境界（昇格）を統制点とする。リソースの語彙・タグ・マウントテーブルを含む詳細は [resources.md](resources.md) を参照。

- 成果物として残るものは必ずバージョン管理された shared 層を通る
- 成果物レビュー関門の承認 = マージ、と対応づけられる
- コミットの名義・来歴の規約は [identity.md](identity.md) を参照
